## 4. Rules (2.0's lane rules, renamed; what changes) (applied by 2.1-02: see `tracks/README.md`)
`hoenn-docs/lanes/README.md` section 3 applies with "track" for "lane". 2.1-02 (track A's first part) sets up the shared structure, the way 2.0's setup PR did, so neither track edits shared files for structure later:
1. **IDs.** 2.1-02's block (512 flags incl. 64 daily + 64 weekly, 64 vars) gets one section per track in `include/constants/hoenn_events_2_1.h`, with `HOENN_TRACK_{A,B}_*` base/count names checked at build time (like `src/hoenn_flags.c` does for the lanes). Proposed split: general flags A 192 / B 160 / shared tail 32 (the journal's ~90 heard flags are track A's, since A3 writes them for 2.0's events; later parts take heard flags from their own track); daily 28 / 28 / 8; weekly 24 / 32 / 8 (B's chains and weekends are weekly); vars 28 / 28 / 8. 02 measures the real needs first and may move the line; its PR says so.
2. **Phone call IDs:** track A 100–129, track B 130–159 (2.0 used 1–99). One chain: `HoennLaneBDueCall()` → `Hoenn21ADueCall()` → `Hoenn21BDueCall()`.
3. **Files:** `src/hoenn_2_1_a.c` / `_b.c`, `data/scripts/hoenn_2_1_a.inc` / `_b.inc`, specials blocks per track in `data/specials.inc`. A system part may have its own file (the journal, the swarms, scene streaming), named in its notes.
4. **Docs:** status in `hoenn-docs/tracks/track-a.md` / `track-b.md` (only that track's builder edits its file; claims on shared things go there, one line each); CLAUDE.md gets "Track A sizes" / "Track B sizes" tables (whole-ROM rows measured after merging `hoenn`) and "Track A notes" / "Track B notes" sections; the playtest checklist gets a section per track.
5. **Hint NPCs** are keyed (as since the lane setup); journal entries are keyed too.
6. **Generated map.json changes** (people's Pokémon, followers, overworld Pokémon, hints, buildings) go through `tools/hoenn/regen_all.sh` after every merge, never by hand-merging; B16–B17 touch almost every town, so track A re-runs regen after syncing instead of resolving those files.
7. **Merging and reviewing:** unchanged from 2.0. Order when two PRs are ready: the one the other track waits for (02, 03, 01's approval, 14), then review fixes, then the older one.
8. **Budget:** 2.1 has ~250 KB release (2.1-plan.md section 19). Soft budget **110 KB per track**, ~30 KB for the join. A part over 15 KB says why in its PR. The debug build stays under 32 MB.
